# 兼容性说明

主题针对 Windows 的 MSIX 版 Codex，使用 `OpenAI.Codex` 包发现及系统应用激活接口，不依赖固定的 WindowsApps 版本路径。

## 已处理的兼容性问题

- 调试发现同时检查 IPv4 和 IPv6 回环地址，拒绝远程或端口不匹配的 WebSocket。
- 仅注入原生 `app://-` 页面，排除网页、本地文件页面和要求透明的桌宠悬浮页。
- 将注入绑定到会话，跟踪缓存页面、导航和新窗口，避免不同修订的样式互相覆盖。
- 为通知摘要使用自适应行高，保留普通聊天列表的紧凑布局。
- 为收起侧栏提供不透明悬浮列表，并补齐窄窗口的悬停交互。
- 调整首页选项面板、模板列表、返回入口及滚动边界，避免装饰覆盖输入区。
- 首页四个入口按主内容区宽度切换四列或两列两行，不再使用固定卡宽的横向列表；侧面板、收起侧栏及低高度窗口保留完整入口，长草稿仍沿用避让规则。
- 首页卡片的清晰照片按原始比例及当前卡片高度计算宽度，渐变跟随照片自身边缘；同源照片延展底图，避免宽高比变化时出现纯色空区及竖直接缝。
- 同步原生输入栏表面色；多行模式下让按钮区域透出主题背景，消除底部灰色长条，并保留原生控件布局。
- Windows 混合 DPI 双屏下，记录窗口最小化前的物理尺寸；同屏同 DPI 恢复后仅纠正异常增大，避免客户端沿用另一块屏幕的最小窗口高度。最大化、手动移动/缩放、显示器或工作区变化时不干预。
- 区分主题加载成功与原生页面空白；恢复工具在没有草稿时最多重新加载一次空白主页面。

## 验证范围

历史完整视觉验收覆盖客户端 `26.1007.2314.0`。1.2.0 的交付测试和较新客户端的有限检查见 [发布验证](release-validation.md)。自动打包测试不能替代对所有原生页面的人工检查。

2026-10-30 在客户端 `26.1023.6621.0` 上针对本次问题验证：使用当前原生组件的隔离副本覆盖宽窄窗口、1/3/15/60 行和展开状态，共 32 组渲染检查；真实外接屏（100%）最小化恢复后保持 1240×840 像素，笔记本缩放为 200%。另有 12 项恢复策略测试覆盖最大化、跨屏、DPI/工作区变化等边界。隔离渲染检查不等于所有页面的端到端验收。

客户端升级后，应在宽窄窗口分别检查首页、对话、通知、设置、终端、首页选项和悬浮侧栏。诊断计数为 0 说明相关组件没有被实际检查，不能据此判定兼容。

同一客户端请只保留一个主题 watcher。切换安装目录或源码目录前，应在旧目录设置对应的 `CODEX_THEMES_HOME` 并执行 `restore`。

窗口恢复兼容处理使用 Windows 自带的 WinEvent 和 PowerShell/.NET，随 watcher 启停，不修改客户端安装文件、系统缩放或兼容性设置。若 helper 无法启动，错误写入 watcher 日志，主题注入继续运行。
